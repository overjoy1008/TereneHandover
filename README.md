# TERENE Workspace Overview

이 디렉토리는 TERENE 서비스 운영에 필요한 프론트엔드 코드, API 서버, 알림 처리 서버, 결제 확인 서버를 함께 모아둔 워크스페이스입니다. 각 디렉토리는 역할이 분리되어 있으며, Framer 기반 화면 구성부터 PostgreSQL 연동, 예약 후속 처리, Toss Payments 결제 확인까지 전체 흐름을 구성합니다.

## 1. `terene-framer-frontend`

이 디렉토리는 Framer의 `Assets` 탭 아래 `Code` 섹션에 들어가는 코드만 따로 모아둔 프론트엔드 코드 저장소입니다. 즉, 디자이너가 Framer에서 직접 사용하는 `.tsx`, `.ts` 코드 컴포넌트와 코드 오버라이드들을 정리한 공간입니다.

Framer는 디자이너 친화적인 도구이지만, 일반적인 웹 개발 환경처럼 GitHub 기반 협업, 외부 라이브러리 설치, 데이터베이스 직접 연동 같은 기능은 지원하지 않습니다. 대신 `code override`와 `code component`만 지원하므로, TERENE 사이트에서 필요한 예약, 결제, 로그인, 회원 기능, 관리자 페이지, 각종 위젯과 버튼, 테이블 UI 등은 모두 이 제약 안에서 React 기반으로 구현되어 있습니다.

외부 시스템과의 연동은 Framer 내부에서 직접 이루어지는 것이 아니라, `fetch` 요청을 통해 별도의 API 서버와 통신하는 방식으로 구성되어 있습니다. 이를 통해 PostgreSQL 기반 데이터 처리, SOLAPI 알림 발송, Toss Payments 결제 흐름 같은 외부 기능을 연결합니다.

또한 Framer에서는 일반적인 React의 `useState` 대신 `useStore`를 중심으로 상태를 관리합니다. 예를 들어 로그인한 회원 정보, 성인/아동 인원 수, 멤버십 적용 여부, 예약 조건, 쿠폰 및 마일리지 상태 등 TERENE 예약 흐름에 필요한 대부분의 상태는 `useStore`를 통해 유지되고 여러 코드 컴포넌트에서 함께 참조됩니다.

## 2. `terene-db-server`

이 디렉토리는 PostgreSQL 데이터베이스와 직접 통신하는 API 서버입니다. 프론트엔드나 다른 내부 서버가 필요한 데이터를 읽어오고, 새로운 데이터를 추가하고, 기존 데이터를 수정하거나 삭제하는 기능을 담당합니다. 이 서버는 GitHub 저장소로 관리되고 있으며, Render에 Web Service 형태로 배포되어 운영됩니다.

실질적으로 TERENE 서비스의 데이터 접근 계층 역할을 하며, 예약 정보, 회원 정보, 쿠폰/마일리지, 관리자 설정값, 일정 관련 데이터 등 서비스 운영에 필요한 대부분의 영속 데이터를 이 서버를 통해 다루게 됩니다.

즉, Framer 프론트엔드가 직접 데이터베이스에 접근할 수 없기 때문에, 이 서버가 중간에서 안전하게 요청을 받아 데이터베이스 작업을 수행하는 핵심 API 레이어라고 볼 수 있습니다.

## 3. `terene-notifier-server`

이 디렉토리는 예약 후속 처리와 알림 자동화를 담당하는 서버입니다. 이 서버 역시 GitHub 저장소로 관리되고 있으며, Render에 Web Service 형태로 배포되어 운영됩니다. 역할은 크게 두 가지입니다.

첫째, `cron`을 이용해 30분마다 데이터베이스를 점검하고, 체크인/체크아웃과 관련된 상태 변화를 확인합니다. 그 결과에 따라 필요한 업데이트를 반영하고, 알림톡 전송 같은 후속 작업을 자동으로 수행합니다.

둘째, 예약 흐름에서 필요한 다양한 비즈니스 로직을 `useCase` 단위로 처리합니다. 예를 들어 A/C/E/F/G 등으로 구분된 시나리오에 따라 캘린더, 회원, 쿠폰 등 관련 테이블을 업데이트하고, 필요한 경우 SOLAPI를 이용해 알림톡을 전송합니다. Framer에서 요청이 들어오면 즉시 무거운 작업을 처리하는 대신 Queue에 적재한 뒤 순서대로 실행하여 안정적으로 예약 프로세스를 운영할 수 있게 합니다.

정리하면 이 서버는 단순 알림 전송기라기보다, 예약 프로세스의 비동기 처리와 운영 자동화를 맡는 워커/오케스트레이션 서버에 가깝습니다.

## 4. `terene-toss-server-api`

이 디렉토리는 Toss Payments 결제를 보조하는 경량 API 서버입니다. 기능 범위는 크지 않지만, TERENE 결제 흐름에서 반드시 필요한 역할을 합니다. 이 서버 또한 GitHub 저장소로 관리되고 있으며, Render에 Web Service 형태로 배포되어 운영됩니다.

Framer만으로는 Toss Payments 결제 완료 이후의 서버 측 검증과 `confirm` 처리를 안정적으로 수행할 수 없기 때문에, 별도의 API 서버가 필요합니다. 이 서버는 Toss Payments API와 통신하여 결제가 정상적으로 승인되었는지 확인하고, 프론트엔드가 직접 처리하기 어려운 결제 검증 단계를 담당합니다.

즉, 이 디렉토리는 결제 기능 전체를 담당하는 대형 서버라기보다, Framer 기반 프론트엔드가 한계 없이 Toss 결제 흐름을 완성할 수 있도록 지원하는 결제 확인 전용 서버입니다.
